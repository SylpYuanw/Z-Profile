# ZForge

**多站点爬虫聚合工作台**

把散着的独立爬虫脚本，收进一个统一的 Web 界面：一处派活、实时看日志、账号池自动轮换、结果统一入库、页面直接分析。

---

## 它解决什么问题

**改造前** —— 一个网站一个脚本，一个脚本一个窗口，账号各自硬编码：

```
爬 B站   →  开一个 tkinter 窗口，Cookie 写死在脚本里
爬 淘宝  →  再开一个窗口，另一个 Cookie 又写死在另一个脚本里
加第 3 个 →  再开一个，再抄一遍账号逻辑
```

**改造后** —— 一套服务层，所有爬虫共用：

```
                  ┌────────────────────────────────────┐
                  │  ZForge（一个页面）                 │
   派活  ────────►│  配任务 → 点开始 → 挂机 → 回来看结果 │
   账号  ────────►│  账号池自动轮换，失效自动冷却        │
   数据  ────────►│  统一入库，跨网站可联合查询          │
                  └────────────────────────────────────┘
```

## 快速开始

```bash
pip install -r 05_Web服务/requirements.txt
python 05_Web服务/run.py
```

Windows 双击 **`启动.bat`**。启动器会检查依赖，确认服务就绪后打开浏览器；
CMD 窗口会保留，显示实际访问地址与停止说明。默认尝试 8765～8804，端口被占用时顺延；
重复启动会复用本项目已有服务。依赖缺失时会显示安装命令，不会静默退出或自动安装。

按 Ctrl+C 停止服务，看到「已停止」后可关闭窗口（若 CMD 询问终止批处理，输入 Y）。
关闭网页不会停止服务。启动或运行失败时查看窗口错误，以及 `05_Web服务/data/startup.log`；
`05_Web服务/data/service-status.json` 记录本次启动状态、进程及实际 URL。

账号入口：左侧 **采集 → 账号池**。选择站点用途池 → 「打开登录页添加账号」→ 填写管理手机号 →
在独立 Edge 窗口中扫码或手机登录 → 自动获取 Cookie 并加密保存 → 回到采集页配置任务。
手机号由用户填写，网站通常只提供掩码或平台用户 ID；不推测完整手机号。默认用手机号命名，
可修改显示名称，账号资料保留手机号。当前逐个账号登录；批量手机授权队列待做。
工作流每步可独立选池，用「仅保存配置」保存后重复使用。手动 Cookie 文件导入保留为高级方式。

首页先选择 B站、淘宝等项目；进入后选择该项目的当前采集或历史数据集，再看明细或分析。
仅接入爬虫采集数据；外部 LLM 网关记录不注册、不展示、不提供查询或导出。
各平台的数据、不同来源的数据集分别读取。B站互动展示动作总量和每百次播放的互动次数，
说明公式、样本覆盖与限制，不把动作次数称作观众人数或实际完成“三连”的人数。

## 关键设计

**1. 为什么必须有本地后端，不能是纯网页？**

浏览器 JavaScript 被安全模型禁止启动本地进程、禁止跨域读取目标站点响应、禁止读任意磁盘文件。所以"纯网页点一下真的去爬"物理上不成立。

**2. 为什么账号池要单独成模块？**

多账号轮换、Cookie 失效检测、冷却退避，这些逻辑如果散在每个爬虫里，加一个网站就要抄一遍。集中之后：所有爬虫共用一个池子，策略改一次全局生效，凭据统一加密。

**3. 一个爬虫 = 一个文件**

`01_网页爬虫/<站点>/crawler.py` 导出 `META` 和 `run(ctx)` 即可。
**加新爬虫不改前端、不改内核** —— 前端按 `META.params` 自动生成表单。

**4. B站为什么用 API 而不是浏览器抓详情？**

实测对比（本机，2026-10）：

| 路线 | 每视频耗时 | 抗改版 |
|---|---|---|
| 原做法（每个视频开一次浏览器 + XPath） | ~10s | 弱 |
| 浏览器 + 页面 JSON | 3.1s | 中 |
| **公开 API** | **0.58s** | **强** |

35 个视频：原来 350 秒，现在 20 秒，而且拿到的是干净整数而不是 "2069.3万" 这种文本。

**5. 当前运行模式**

当前需要本地后端；无后端时显示连接提示。单文件展示版、JSON 快照和浏览器内 SQL
仍在后续计划中，不能把已分发 sql.js 等同于已支持离线查询。
淘宝分析在暂无新采集结果时读取历史库的真实商品，并标注历史来源。

## 安全

- 账号凭据（Cookie 等）加密后存入 `02_账号池/数据/accounts.db`；手机号、显示名称、平台身份和使用记录等元数据仍可能以明文保存，因此整个数据库不得提交。
- 加密密钥默认存放于 `%APPDATA%\ZForge\`，在项目目录之外；这不代表项目里的其他数据可以直接公开。
- SQL 执行接口只允许 `SELECT` / `WITH` / `EXPLAIN`，由 SQLite authorizer 拦截写入、`ATTACH`、`PRAGMA`；使用只读连接，限制返回行数。
- 因此：**不要提交 `%APPDATA%\ZForge\`，也不要提交任何 `.key` / `.salt` 文件。**
