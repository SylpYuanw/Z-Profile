# 前端规划

> 本文是设计目标。2026-10-16 已复核当前 9 类页面，系统页合并在 `logs.js`，
> 工作流页位于 `taskflow.js`。当前 SQL 由后端执行，离线展示仍未实现；
> 淘宝暂无新结果时使用真实历史商品并标记来源。公开版本不附带历史采集数据；实现范围见根目录 README。

> 目标：**好看、好用、不花哨**。
> 面试官打开第一眼觉得"这是正经东西"，而不是"学生练手页面"。

## 二、页面清单

### 1. 工作台（首页）`#/`

一进来就要有"这系统在干活"的感觉。

| 区块 | 内容 |
|---|---|
| 状态条 | 后端状态、Python 版本、已注册爬虫数、数据总量 |
| 采集入口卡片 | 每个爬虫一张卡（由 `/api/crawlers` 自动生成），显示站点、说明、上次运行结果 |
| 近期任务 | 最近 5 条任务，状态标签 + 耗时 |
| 数据概览 | 两个数字 + 一张小折线（近 7 天采集量） |

### 2. 采集页（每个爬虫一个）`#/crawler/{id}`

**同一个模板，参数表单按 `META.params` 自动渲染。**

```
┌─────────────────────────────┬──────────────────────────────────┐
│  参数                        │  实时日志                         │
│  ● 搜索关键词  [python     ] │  18:23:01 INFO  启动 Edge…        │
│  ● 翻页数      [2          ] │  18:23:04 INFO  打开搜索页        │
│                              │  18:23:09 OK    解析到 30 条      │
│  [开始采集]  [取消]          │  ...                              │
│                              │                                   │
│  进度 ████████░░░░ 63%       │                                   │
├─────────────────────────────┴──────────────────────────────────┤
│  本次结果（跑完后出现）                                          │
│  表格 + 图表 + [导出 CSV] [导出 Excel]                          │
└─────────────────────────────────────────────────────────────────┘
```

日志区用等宽字体 + 按级别着色（INFO 蓝 / OK 绿 / WARN 黄 / ERR 红）。

### 3. 数据浏览 `#/data`

左侧数据源 + 表树，右侧表格。支持排序、分页、按标题模糊搜索。

### 4. SQL 实验室 `#/sql`

```
┌────────────────────────────────────────────────────────────┐
│ 数据源 [淘宝历史采集 ▾]        [执行 ⌘↵]  [格式化]  [清空]  │
├────────────────────────────────────────────────────────────┤
│ 1  SELECT title, price, pay_count                          │
│ 2  FROM 显示器                                              │
│ 3  WHERE price > 1000                                      │
│ 4  ORDER BY pay_count DESC                                 │
│ 5  LIMIT 20;                                               │
├────────────────────────────────────────────────────────────┤
│ 结果 17 行 · 3ms          [表格] [图表] [导出]              │
│ ┌──────────┬────────┬───────────┐                          │
│ │ title    │ price  │ pay_count │                          │
│ └──────────┴────────┴───────────┘                          │
└────────────────────────────────────────────────────────────┘
```

SQL 输入框用等宽字体，`⌘/Ctrl + Enter` 执行。预设几条示例查询供点击。

### 5. 运行日志 `#/logs`

所有任务的历史日志，可按爬虫/级别过滤。

### 6. 环境自检 `#/system`

Python 版本、依赖清单（装了/没装）、driver 缓存状态、数据库文件列表。**这一页是给面试官看的**——证明这套东西不是随便糊的。

## 三、视觉规范

| 项 | 决定 |
|---|---|
| 主色 | 石墨深灰底（`#0b0e14`），不用纯黑 |
| 强调色 | 每个爬虫自己的色（B站青、淘宝橙），由 `META.accent` 注入 |
| 文字 | 界面用无衬线（Inter / 微软雅黑），**数据一律等宽字体 + 数字对齐** |
| 圆角 | 卡片 14px、按钮 6px，不要全圆 |
| 阴影 | 克制。只在悬停和浮层用 |
| 动效 | 只做三处：页面切换淡入、数字滚动、进度条过渡。其他一律不动 |
| 主题 | 深色为主，提供浅色切换（面试时打印简历可能用得上） |
| 信息密度 | 提供"舒适/紧凑"切换 |

**要避免的**：
- ❌ 花哨渐变、玻璃拟态堆砌 → 显得廉价
- ❌ 大量 emoji → 不专业
- ❌ 无意义的加载动画 → 拖慢观感

## 四、前端文件划分

```
06_前端/
├─ index.html
├─ css/
│   ├─ tokens.css        设计令牌（颜色/字号/间距），两套主题都在这
│   └─ app.css           组件样式
├─ js/
│   ├─ 核心/
│   │   ├─ util.js       格式化、DOM 辅助、数学（分位数/相关系数）
│   │   ├─ api.js        所有 fetch 调用集中在这，方便统一改
│   │   ├─ router.js     hash 路由
│   │   ├─ ui.js         组件库（卡片/KPI/表格/终端/进度条/弹窗）
│   │   ├─ charts.js     Chart.js 封装（统一观感 + 自动销毁）
│   │   └─ store.js      数据缓存 + 派生统计
│   └─ 视图/
│       ├─ dashboard.js
│       ├─ crawler.js    通用爬虫页（参数表单 + 日志 + 结果）
│       ├─ data.js
│       ├─ sql.js
│       ├─ logs.js
│       └─ system.js
└─ vendor/               离线库（Chart.js / SheetJS / sql.js）
```

**约定**：视图文件只负责"把数据画成 DOM"，不写业务逻辑；计算放 `store.js` 或后端。

## 五、和后端的两种接线方式

同一套视图代码，要能同时吃两种数据源：

```js
// js/核心/api.js 里的核心判断
const 有后端 = await 探测后端();

export async function 取爬虫列表() {
  if (有后端) return fetch('/api/crawlers').then(r => r.json());
  return 内联数据.crawlers;               // 静态展示版
}
```

- **完整版**：后端在线，所有数据实时
- **展示版**：无后端，`index.html` 里内联一份 JSON 快照；采集页的"开始"按钮置灰并注明"展示版不支持实时采集"

## 六、响应式

只保证两档：
- **≥1100px**：完整三栏
- **820~1100px**：导航收窄成图标条，内容单栏

手机不做（本地工具没这个场景）。

`@media print` 下隐藏导航和顶栏。面试官想打印页面留档时干净。
