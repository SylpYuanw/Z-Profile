# 架构说明

> 下文保留早期分层设计草案。实际目录是 `05_Web服务/server/`、
> `01_网页爬虫/<站点>/crawler.py`、`03_统一数据库/`；路由目前集中在 `server/app.py`，
> 数据层位于 `server/store/db.py`。浏览器内 SQL、离线展示和 API 拆分尚未完成。
> 公开版本范围见根目录 README；历史运行数据未随仓库分发。

## 一、为什么必须是 B/S，不能是纯网页

需求是"在页面上点一下，真的去爬"。这件事**纯网页做不到**，有四个硬性障碍：

| # | 障碍 | 说明 |
|---|---|---|
| 1 | 浏览器 JS 无法启动进程 | JS 只有 fetch/XHR，没有任何 API 能启动 `.py` 或 `.exe` |
| 2 | Selenium 需要真实驱动浏览器 | 网页里没有这个能力 |
| 3 | 同源策略 | 淘宝/B站响应没有 CORS 头，浏览器拒绝把内容交给页面 JS |
| 4 | 读不到本地文件 | JS 读不了任意磁盘路径，`taobao_data.db` 拿不到 |

所以：**必须有一个本地运行的 Python 后端**。前端负责好看好用，后端负责真干活。

## 三、一次"点按钮爬取"的完整数据流

```
① 用户在页面上填关键词、点【开始】
        │
        ▼
② 前端 POST /api/tasks  {crawler:"bilibili", params:{keyword:"python", pages:2}}
        │
        ▼
③ api/tasks.py 校验参数（对照该爬虫的 META 声明）
        │
        ▼
④ taskrunner 建任务 → 状态 queued → 丢进线程池
        │
        ├──► 立即返回任务号 {task_id:"t-0001"} 给前端
        │
        ▼
⑤ 前端拿到 task_id 后，立刻开 EventSource
   GET /api/tasks/t-0001/logs   ← SSE 长连接
        │
        ▼
⑥ 工作线程里跑 crawlers/bilibili.py 的 run(ctx)
   · 每做一步 → ctx.log("INFO", "打开搜索页…")
   · 这条日志被推进 logbus
        │
        ▼
⑦ logbus 把日志广播给所有订阅了这个 task_id 的 SSE 连接
        │
        ▼
⑧ 前端把日志一行行追加到终端区（自动滚动）
   同时任务状态 running → 进度条动
        │
        ▼
⑨ 爬完 → 数据经 db.py 归一化写入 data/zforge.db
   → 状态 success，SSE 发一条 done 事件
        │
        ▼
⑩ 前端收到 done → 关闭 SSE → 提示成功 → 刷新数据页
```

## 四、为什么这么分（设计取舍）

| 决定 | 理由 |
|---|---|
| **爬虫跑在线程池，不是子进程** | 好传日志、好取消。缺点是单个爬虫崩溃可能影响主进程——所以 `run()` 外层统一包异常捕获。 |
| **日志用 SSE，不用 WebSocket** | SSE 是原生 HTTP，Flask 直接支持，不需要 `flask_socketio`（本机也没装）。日志是单向推送，SSE 刚好够。 |
| **每个爬虫一个文件 + META 声明** | 加新爬虫只写一个文件，前端自动长出表单。这是"可维护"的关键。 |
| **统一 `items` 表 + 保留原始表** | 归一化后才能做跨网站查询（SQL 实验室）；同时保留原始字段不丢信息。 |
| **静态展示版复用同一套前端代码** | 数据源从"实时接口"换成"内联 JSON"，页面代码不改。 |

## 五、前端能读数据库吗？能

浏览器里跑 SQLite 有两个办法：

| 方式 | 说明 | 用在哪 |
|---|---|---|
| **`sql.js`（WebAssembly 版 SQLite）** | 把 `.db` 文件加载进内存，真执行 SQL | SQL 实验室、数据浏览 |
| **后端代查** | 前端发 SQL → 后端用 Python `sqlite3` 跑 → 返回结果 | 大数据量时用（避免把整个库传到浏览器） |

两种都会做：小库走浏览器直读（零延迟），大库走后端代查。

**MySQL 入口**：同一个 SQL 执行器，数据源可切换。以后装了 MySQL，把连接信息填进去、`mysqldump` 出来的 `.sql` 导入即可，前端不用改。
