# 接口契约

> **规则：任何接口的新增或修改，先改这份文档，再动代码。**
> 前端和后端都以本文档为准。不一致就是 bug。

统一约定：

- 所有接口前缀 `/api`
- 请求和响应都是 JSON，`Content-Type: application/json; charset=utf-8`
- **成功**：HTTP 200 + 直接返回数据体；创建任务/启动工作流返回 202
- **失败**：HTTP 4xx/5xx + `{"error": "错误说明", "detail": "细节"}`
- 时间戳统一用**秒级**整数（Unix epoch），不用毫秒、不用字符串

## 1. 爬虫注册表

### `GET /api/crawlers`

列出所有已注册的爬虫。**前端用它自动渲染界面**——加新爬虫不用改前端。

2026-10-17：爬虫可声明 `collection`（采集方式）和 `authentication`（登录要求）。
`collection.mode` 为 `http` / `selenium` / `hybrid`，`methods` 列出实际使用的方式，
`stages` 为 `[{label, method}]`，说明混合采集各阶段的方式。
`authentication` 为 `{requirement: "none" | "required", credential_types: []}`；
当前淘宝使用 `cookies`，B站不需要凭据。这些字段描述已实现能力，不创建新的执行方式。
旧模块未声明时返回 `collection: null`，登录要求根据原 `needs_account` 补齐。
`account_site` 仍是站点标识，当前不是命名账号池 ID。多池、配置模板与扫码队列见设计稿。

**响应**
```json
{
  "crawlers": [
    {
      "id": "bilibili",
      "name": "B站视频采集",
      "site": "search.bilibili.com",
      "desc": "按关键词搜索视频，抓取播放量/点赞/投币/收藏，计算互动率",
      "accent": "#00a1d6",
      "params": [
        {
          "key": "keyword",
          "label": "搜索关键词",
          "type": "text",
          "required": true,
          "placeholder": "例如：python 教程",
          "help": "多个关键词用逗号分隔"
        },
        {
          "key": "pages",
          "label": "翻页数",
          "type": "number",
          "required": false,
          "default": 1,
          "min": 1,
          "max": 50
        }
      ]
    }
  ]
}
```

`params[].type` 允许的值：`text` | `number` | `select` | `switch`
（`select` 额外带 `options: [{value,label}]`）

## 2. 任务

### `POST /api/tasks` — 派活

**请求**
```json
{
  "crawler": "bilibili",
  "params": { "keyword": "python", "pages": 2 }
}
```

**响应（202）**
```json
{
  "task_id": "t-20261012-0001",
  "state": "queued",
  "created_at": 1791234567
}
```

**错误**
| 码 | 场景 |
|---|---|
| 400 | `crawler` 不存在 / 必填参数缺失 / 参数类型不对 |
| 409 | 同一个爬虫已有运行中的任务，且该爬虫声明了 `exclusive: true` |

---

### `GET /api/tasks` — 任务列表

包含当前进程任务与已落库历史，按创建时间倒序。服务重启时，遗留的 queued/running
记录转为 failed，并注明服务重启中断；不会自动重新采集。删除任务同时删除持久记录。
响应额外提供 `counts`（各状态数量、total、active）。
任务条目使用顶层 `items`、`errors`、`error`、`duration`、`account`，不使用嵌套 `stats`。
`items` 是成功交给数据层的记录数，包含去重记录，不等于新增数据库行数。
爬虫报错且无结果、数据层抛错均返回 failed；部分结果伴随非致命错误时保留 errors。

**查询参数**

| 名 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `crawler` | string | 全部 | 按爬虫过滤 |
| `state` | string | 全部 | `queued`/`running`/`success`/`failed`/`canceled` |
| `limit` | int | 50 | 最多返回几条 |

**响应**
```json
{
  "tasks": [
    {
      "task_id": "t-20261012-0001",
      "crawler": "bilibili",
      "crawler_name": "B站视频采集",
      "params": { "keyword": "python", "pages": 2 },
      "state": "running",
      "progress": 0.63,
      "message": "正在解析第 2 页…",
      "created_at": 1791234567,
      "started_at": 1791234568,
      "finished_at": null,
      "items": 35, "errors": 0, "error": "", "duration": 12.5, "account": ""
    }
  ]
}
```

### `GET /api/tasks/{task_id}` — 单个任务详情

同上单条结构。额外带 `error`（失败时的异常摘要）。

### `POST /api/tasks/{task_id}/cancel` — 取消

**响应** 为完整任务对象；取消请求只设置标记，响应可能仍为 queued/running。
（运行中的任务收到"取消"标记后，在下一个检查点退出，不是强杀）

### `DELETE /api/tasks/{task_id}` — 删除记录

只允许删除已结束（success/failed/canceled）的任务。

## 3. 实时日志（SSE）

### `GET /api/tasks/{task_id}/logs`

**Server-Sent Events**，`Content-Type: text/event-stream`

**事件类型**

| event | data | 什么时候发 |
|---|---|---|
| `log` | `{"ts":1791234568,"level":"INFO","msg":"打开搜索页…"}` | 爬虫每写一条日志 |
| `state` | `{"state":"running","progress":0.35,"message":"..."}` | 状态或进度变化 |
| `done` | `{"state":"success","items":35,"errors":0,"duration":12.5,"error":""}` | 任务结束（发送后服务端关闭连接） |

`level` 允许的值：`INFO` `OK` `WARN` `ERR` `SQL`

**前端约定**：拿到 `task_id` 后**立刻**连 SSE；收到 `done` 后主动关闭，避免连接泄漏。

## 4. 数据

### `GET /api/data/sources` — 有哪些数据源

```json
{
  "sources": [
    { "id": "zforge", "name": "工作台数据库", "path": "data/zforge.db", "kind": "sqlite", "writable": true },
    { "id": "taobao_legacy", "name": "淘宝历史采集", "path": "03_数据库/taobao_data.db", "kind": "sqlite", "writable": false },
    { "id": "bili_legacy", "name": "B站历史采集", "path": "03_数据库/视频简单信息.db", "kind": "sqlite", "writable": false }
  ]
}
```

### `GET /api/data/{source_id}/tables` — 表清单

```json
{
  "tables": [
    { "name": "显示器", "rows": 17, "columns": [
      { "name": "id", "type": "INTEGER" },
      { "name": "title", "type": "TEXT" }
    ]}
  ]
}
```

### `GET /api/data/{source_id}/rows` — 取行

**查询参数**：`table`（必填）、`limit`（默认 100，上限 2000）、`offset`、`order`、`dir`、`q`（模糊搜索标题类字段）

```json
{
  "table": "显示器",
  "total": 17,
  "offset": 0,
  "limit": 100,
  "columns": ["id","title","price"],
  "rows": [[1,"AOC 27英寸",1299.0]]
}
```

> **注意**：`rows` 用**二维数组**，不用对象数组。列名只在 `columns` 里出现一次，大数据量时体积能小一半。

导出由前端基于已加载的结果生成 CSV / Excel，目前没有后端 export 接口。
另有 `GET /api/data/items`（归一化记录）和 `GET /api/data/stats`（统一库统计）。
历史数据源仅注册 `bili_legacy` 和 `taobao_legacy`。所有数据接口共用此白名单，
外部 LLM 库不注册；表列表、明细、项目数据集与 SQL 均不提供访问。原文件保留。

## 5. SQL 执行

### `POST /api/sql` — 跑一条 SQL

**请求**
```json
{
  "source_id": "taobao_legacy",
  "sql": "SELECT title, price FROM 显示器 ORDER BY price DESC LIMIT 10"
}
```

**响应**
```json
{
  "columns": ["title","price"],
  "rows": [["AOC 27英寸",1899.0]],
  "row_count": 1,
  "elapsed_ms": 3
}
```

**安全约束**

| 规则 | 说明 |
|---|---|
| 只允许 `SELECT` / `WITH` / `EXPLAIN` | 后端解析首关键字，其他一律拒绝 |
| 禁止多语句 | SQLite execute 只执行一条语句；字符串中的分号允许 |
| 禁止写操作 | SQLite authorizer 只允许读取、SELECT、函数和递归查询；不按字符串包含关系误拦字段/字面量 |
| 限制返回行数 | 默认 1000，上限 5000，通过 fetchmany 截断，不改写用户 SQL |
| 只读连接 | 历史库用 `file:xxx.db?mode=ro` 打开 |

> 这条接口是给**你自己用**的，但约束照做——面试官一定会试 `DROP TABLE`。

## 6. 系统

### `GET /api/health`

```json
{
  "ok": true,
  "version": "0.1.0",
  "python": "3.13.13",
  "uptime_s": 120,
  "crawlers": 3,
  "deps": { "selenium": true, "openpyxl": false }
}
```

前端顶栏用这个显示"后端已连接"。`deps` 里为 `false` 的，对应的爬虫页面要给出提示而不是直接报错。

```json
{
  "error": "参数校验失败",
  "detail": "字段 pages 期望 number，收到 \"abc\""
```

## 7. 账号池与工作流

2026-10-18 第二轮补充：账号增加 phone（用户填写的管理手机号，与平台身份分开）、label；
PATCH /api/accounts/{id} 修改显示名称/手机号，空名称默认手机号；改名不改变账号 ID、凭据和历史。
GET/POST /api/account-logins 管理网页登录录入，POST 请求 {pool_id,phone,label?,update_account_id?}；
GET /api/account-logins/{id} 查询，POST /api/account-logins/{id}/cancel 取消。
后端打开独立浏览器官方登录页，用户自行扫码/手机登录，检测到登录 Cookie 后加密保存到所选池。
请求不接收网站密码、短信验证码；响应不含 Cookie。登录状态仅在明确网站验证后标有效，否则待检测。

数据入口按平台项目隔离：GET /api/data/projects 返回独立项目和数据集目录；
GET /api/data/projects/{project_id}/datasets/{dataset_id} 仅返回选定项目的单个数据集，
包含 columns/rows/items（支持专用分析时）/total/limit/truncated。上限 5000 条，截断须在页面说明。
各分析模板只使用所选数据集的已加载记录；导出与筛选也限定当前数据集。项目只是平台分类，不新增多用户/多工作区模型。
统一库按 crawler source 过滤，历史库按原表读取；不自动回退或拼接另一个库。

2026-10-18：以下命名池、导入和任务绑定接口已实现。导入合计上限 2 MB、1～20 文件；
过大返回 JSON 413，其余文件校验错误按文件返回 failed。导入只做本地完整性/身份/时间戳校验。
采集器可在 report_account 中显式提供 login_status（valid/expired/unknown）及检测时间；
普通采集异常不改变登录状态。逐账号扫码队列与独立运行配置模板未提供接口。

### 2026-10-18 账号池管理

- `GET /api/account-pools[?site=...]`：返回 pools（名称、站点、成员数、可用数、启停、默认池、选号策略）。
- `POST /api/account-pools`：创建 `{site,name,strategy}`，strategy 为 least_used / round_robin。
- `PATCH /api/account-pools/{id}`：修改 name / enabled / is_default / strategy；不允许修改站点。
- `GET /api/account-pools/{id}`：池详情、成员、可加入的同站点账号与汇总。
- `POST /api/account-pools/{id}/members`：以 `{account_id}` 添加已有同站点账号。
- `DELETE /api/account-pools/{id}/members/{account_id}`：移出该池，保留账号与其他成员关系。
- `POST /api/account-pools/{id}/import`：multipart/form-data，files（一个或多个 Cookie JSON 文件）、label（单文件可选）、update_account_id（单文件显式更新）。
  返回 results，每项为 imported / updated / failed 及安全错误描述；不返回凭据。
  文件内容直接在后端校验，不落明文文件；重复身份/同名账号不会自动覆盖。更新核对身份且不得更新正在使用的账号。
- `GET /api/accounts` 保持兼容，并新增 credential_kind、login_status、login_checked_at、pool_ids、busy。

池详情页使用 `#/accounts?pool=ID`，导入、成员和统计仅针对当前选中池。
账号是全局身份，可加入多个同站点池；租约与日额度按账号统一计算。
旧账号迁入站点默认池，凭据不变；本机已有淘宝过期问题仅在首次迁移时记录到旧账号。
导入 Cookie 后状态为「未检测」或根据本地关键 Cookie 时间判「已过期」，不声称已验证网站有效性。

`POST /api/tasks` 新增顶层 `account_pool_id`；省略时使用站点默认池。
工作流每步也可保存 account_pool_id。后台验证站点、池启用状态与凭据类型。
任务对象新增 account_pool_id / account_id；所选池随任务持久化，重启后可查询。
领取成功后每任务固定一个账号；同账号只能有一个有效租约，跨池也不能并发占用。
任务结束/取消/失败释放租约，运行中续约，失去租约后在取消检查点停止。

### 启动状态

`GET /api/health` 增加 `project_root` 和 `pid`，供启动器判断是否为本项目的已有服务。
启动器实际绑定端口后才显示地址，确认健康检查成功后打开浏览器。
状态保存在 `05_Web服务/data/service-status.json`（状态、地址、PID、日志路径），
入口日志为 `05_Web服务/data/startup.log`，不包含账号凭据。

- `GET /api/accounts[?site=...]`：accounts / summary / sites。凭据不会返回。
- `GET /api/accounts/{id}/history`：使用记录；`POST /api/accounts/{id}/state`：修改轮换状态。
- `DELETE /api/accounts/{id}`：移除账号。healthy 仅表示池内轮换状态，不保证网站登录态有效。
- `GET /api/workflows`：workflows / runs；`POST /api/workflows`：保存 id / name / steps。
- `DELETE /api/workflows/{id}`：删除模板；`POST /api/workflows/{id}/run`：启动并返回 202。
- `GET /api/workflows/runs`：运行记录；`POST /api/workflows/runs/{id}/cancel`：请求取消。

工作流步骤为 crawler / params / label / on_fail / retries。on_fail 为 continue 或 abort；
兼容 retry（重试耗尽后中止）。工作流记录在重启后仍可查询，遗留 running 标为 failed。
日志目前仅有进程内缓冲，重启后可以查询任务结果，但不能回放上个进程的日志。
