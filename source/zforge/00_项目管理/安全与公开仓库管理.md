# 安全与公开仓库管理

本文记录项目运行时可能生成个人信息、凭据或本机环境信息的位置。公开仓库只提交源码、测试和经过复核的文档；不要把本机运行数据复制进仓库。

## 需要留在本机的数据

| 位置 | 可能包含的内容 | 提交处理 |
|---|---|---|
| `01_网页爬虫/原始代码/taobao_cookies.json`、`04_数据可视化/taobao_cookies.json` | 明文淘宝 Cookie、平台账号标识和登录态 | 不提交；若曾公开，撤销/更新对应登录态 |
| `02_账号池/数据/accounts.db` | 加密凭据，以及手机号、账号显示名、池成员和使用记录等资料 | 整个数据库及 `-wal`、`-shm` 文件均不提交 |
| `03_统一数据库/*.db` | 历史采集结果或其他本机导入的数据；旁边可能有 SQLite `-wal`、`-shm` 文件 | 不提交数据库文件及伴随文件 |
| `05_Web服务/data/*.db` | 工作台采集结果、任务历史、工作流配置 | 不提交数据库文件及伴随文件 |
| `05_Web服务/data/startup.log` | Python 可执行文件位置、项目绝对路径、日志路径、启动过程和本机访问 URL | 每次运行都可能更新；不提交，也不要原样公开粘贴 |
| `05_Web服务/data/service-status.json` | 进程号、服务 URL、日志绝对路径、运行状态 | 每次启动都会写入；不提交 |
| `05_Web服务/run.py` 的控制台 / 文件日志 | 启动时记录 Python 版本、解释器绝对路径、项目路径、端口和异常堆栈；文件写入 `05_Web服务/data/startup.log` | 控制台内容和文件日志都先按本机信息处理；分享前检查并脱敏 |
| `05_Web服务/server/core/logbus.py` 的内存日志 | 每任务最近 800 条、全局最近 4000 条，经网页运行日志和 SSE 显示；爬虫可能记录账号显示名、搜索关键词、商品标题及目标 URL | 当前只保存在进程内存，但页面截图、复制内容或未来增加持久化时可能外泄；不要将手机号、Cookie、请求头、响应正文写入 `ctx.log` |
| `01_网页爬虫/原始代码/` 中的旧脚本 | 旧版脚本会在终端打印平台账号标识/昵称、页面片段或 Cookie 相关诊断信息 | 该目录不进入公开副本；若在本机运行，终端记录也不要直接公开 |
| `04_数据可视化/*.json`、`*.xlsx`、`页面快照/` | 真实采集商品、平台页面原始内容、商品或用户标识 | 不提交；演示数据应使用人工构造且可公开的数据 |
| `04_数据可视化/验收/` | 应用截图；登录、账号管理或浏览器页面截图可能暴露标识、登录态或环境细节 | 逐张复核并脱敏后才考虑提交 |
| `%APPDATA%\ZForge\` | 账号凭据加密密钥和盐值 | 位于项目目录之外；绝不复制进仓库或备份到公开位置 |
| `.env*`、`*.key`、`*.salt`、Cookie 导出文件 | 外部服务凭据、加密密钥或登录态 | 不提交；按需使用本机配置 |

当前服务启动日志由 `05_Web服务/run.py` 写入 `05_Web服务/data/startup.log`，状态文件写入同目录的 `service-status.json`。账号池数据库在 `02_账号池/数据/`，工作台数据库在 `05_Web服务/data/`；旧采集数据库在 `03_统一数据库/`。运行时创建目录或文件时，按上表作为本机数据处理。

当前爬虫通过 `ctx.log` 写入 `LogBus`，再由运行日志页面 / SSE 展示；它不等同于 `startup.log`，目前在内存中缓冲。淘宝采集日志包含账号显示名及关键词/URL，显示名如果使用手机号就会连带暴露手机号。任何终端录屏、日志截图和复制到问题单的片段，都应先按可能包含个人数据处理。不要记录 Cookie 值、认证头、手机号或完整响应正文。

## 提交前检查

1. 查看 `git status --short` 和 `git diff --cached --name-only`，确认没有数据库、日志、Cookie、截图或采集数据。
2. 检查新加入的源码、文档和测试中的真实手机号、邮箱、令牌、私钥、绝对路径和浏览器 Cookie。
3. 检查提交历史；`.gitignore` 只能阻止后续误加，无法从已有 Git 历史中移除文件或撤销已经公开的凭据。
4. 一旦凭据进入公开仓库，即使随后删除文件，也应按已泄露处理并撤销或轮换。

公开仓库的忽略规则位于仓库根目录 `.gitignore`。新增数据文件类型或运行日志位置时，同步更新忽略规则和本文。

## 维护副本

原始开发目录与公开 Git 副本独立，不会自动同步。后续更新按文件挑选源码或测试，先检查改动，再同步；不要整目录覆盖，也不要复制运行数据库、Cookie、日志或采集输出。公开副本启动后会生成新的本机数据，仍须在每次提交前检查暂存内容。
